## Official Documentation

Consult the official Mathlib documentation at: `https://github.com/leanprover-community/mathlib4/tree/{version}`

**Version resolution.** The version is not fixed: this project pins it in `lean/lake-manifest.json`. Before relying on version-specific behaviour or documentation:

1. Read `lean/lake-manifest.json` in this project and apply the pattern `"rev":\s*"(?P<version>[0-9a-f]{40})",\s*"name":\s*"mathlib"`; its `version` group is the pinned version.
2. Run `python3 scripts/lean_docs.py`. It prints the resolved version and documentation URLs; when it succeeds, its output takes precedence over step 1.
3. Consult `https://github.com/leanprover-community/mathlib4/tree/{version}` with `{version}` replaced by the resolved version.

`v4.34.1` is the generation-time default recorded when this document was generated; use it only when the pin file is missing or does not match, and say so.

Verify configuration options, API signatures, and version-specific behavior against this
documentation before making changes.

## Common Patterns & Pitfalls

- Import the narrowest modules needed (e.g. `Mathlib.Tactic.Ring`), not all of `Mathlib`; this keeps source builds fast when the cache is unavailable.
- Never invent declaration names: confirm each with `#check` or the docs before citing it in a tactic plan or a dossier.
- `exact?`/`apply?` results are suggestions; keep the explicit term they print, not the search call.

## Config Management

Current configuration lives in: `lean/lakefile.toml, lean/lake-manifest.json`

Before any configuration change:
1. Read the current configuration file
2. Verify the proposed change is backward-compatible with `(version pinned in lean/lake-manifest.json; generation-time default v4.34.1)`
3. If the change modifies security-sensitive settings, request clearance from `@security`
4. Back up the existing config by saving as `<filename>.backup` before writing
5. Apply the change and verify the tool starts correctly

## Invocation Procedure

1. Read current config from `lean/lakefile.toml, lean/lake-manifest.json` to confirm expected state
2. Run: ``

4. Check exit code — non-zero exit is a failure; log and escalate

## Verification

After every invocation, verify:
- All expected output files are present
- Output is not empty (zero-byte output indicates silent failure)
- No error or warning lines appear in the log that weren't present in the previous successful run

## Cleanup

After successful verification:
- Remove intermediate/temporary files generated by `Mathlib` (not final outputs)
- Compress large log files if > 10 MB
- Do not remove `lean/lakefile.toml, lean/lake-manifest.json`

## When to Involve the Team

Raise with `@orchestrator` (and `@security` for credentials/access) when:
- Mathlib exits non-zero on two consecutive runs after config review
- Config state is inconsistent with `(version pinned in lean/lake-manifest.json; generation-time default v4.34.1)` requirements
- A security-sensitive setting requires modification
